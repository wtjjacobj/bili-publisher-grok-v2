# B站投稿文案“证据优先”质量设计

## 背景

当前流程仅把来源元数据、用户说明和视频在 20%、50%、80% 位置的三张截图交给文案模型。生成结果只接受数量、长度、重复和文件路径检查，不验证语义贴合度。

近期任务暴露出以下可复现问题：

- 蒙古国派对视频的核心反差是结尾出现马匹，但三张固定截图全部停留在女 DJ，导致标题退化为普通派对描述。
- 来源账号 `The Werewolf` 被当成电影名称。
- 未生成字幕的任务在简介和标签中声称“已添加中文字幕”。
- 星球大战婚礼出现未经充分证据确认的人物标签。
- 标签通过中英文重复和近义词凑满十个，标题则反复使用“发生了什么”“现场画面”等空泛表达。

## 目标与优先级

系统必须先准确理解视频，再生成面向中文 B 站读者的标题、简介、标签和分区。

优先级从高到低为：

1. 事实准确，不虚构人物、作品、地点、对白、结果或字幕状态。
2. 紧扣视频真正的主体、动作、转折和结果。
3. 表达具体，包含可搜索的有效实体和事件。
4. 在前三项满足的前提下提高吸引力。

点击吸引力不能覆盖或放宽事实要求。

## 总体架构

流程拆成四个边界清晰的阶段：内容准备、事实分析、文案生成、独立审稿。

### 1. 内容准备

`prepare_video.py` 继续负责下载、探测媒体信息和生成供页面选择的封面，同时新增用于内容理解的证据材料。

#### 关键画面

- 从视频时长的 5%、15%、25%、35%、45%、55%、65%、75%、85%、95% 位置提取十张按时间排序的分析帧。
- 5% 和 95% 用于保证开头与结尾覆盖，防止遗漏结尾反转。
- 页面初始封面仍可保留三张，分析帧单独存放，避免把内部证据图全部展示为封面候选。
- 每帧记录时间戳和路径，写入 `visual_timeline.json`。

#### 语音转写

- 视频存在音轨时，调用本机已安装并已缓存的 Whisper `large-v3-turbo` 模型生成带时间戳的原语言转写。
- 没有有效语音片段时记录 `has_speech: false`；转写成功且有有效片段时记录 `has_speech: true`。
- 转写只用于理解视频，不生成或烧录字幕文件，也不能据此声称“已添加中文字幕”。
- 转写结果保存为 `transcript.json`，包括语言、片段起止时间、原文和置信信息。中文翻译由事实分析阶段完成。

#### 来源结构化

来源信息明确分开：平台、原链接、帖子正文、发布账号、频道、上传日期、来源标签和媒体时长。发布账号不得自动解释为作品名、人物名或原创作者。

`prepare_result.json` 新增分析帧清单、转写路径和媒体语音状态，但保持现有视频和封面字段兼容。

### 2. 事实分析

第一个模型只负责理解，不写投稿文案。输入包括：

- 结构化来源信息和用户补充说明；
- 十张带时间戳的分析帧；
- 原语言转写；
- 视频时长和基本媒体信息。

输出 `content_brief.json`，结构至少包含：

- `video_type`：实拍、影视片段、恶搞、AI 生成、解说等；
- `core_subject`：主要对象；
- `core_event`：视频发生的核心事件；
- `timeline`：按时间排列的关键动作；
- `turning_point` 与 `outcome`：转折和结果，无法确认时为空；
- `hook`：最具体、最有辨识度且有证据的看点；
- `entities`：人物、作品、地点、品牌和事件，包含原文名称、中文名称、实体类型、证据和置信度；
- `source_account`：来源发布账号，与作品实体分离；
- `verified_dialogue`：有转写依据的重要对白；
- `uncertainties`：无法确认或彼此冲突的信息；
- `forbidden_claims`：本次文案不得声称的内容。

事实分析必须将每个关键结论关联到来源文本、转写片段或具体时间点画面。没有证据的实体不得进入“已确认实体”。

### 3. 文案生成

第二个模型只读取 `content_brief.json` 和用户补充说明，不直接从模糊的原帖账号名或零散截图自由联想。

输出结构在现有字段上增加：

- `recommended_title_index`：0 到 4 的整数；
- 内部 `title_reasons`：每个候选对应的核心事实与吸引点，保存用于审稿但不提交 B 站；
- 内部 `tag_evidence`：每个标签对应的事实卡字段或证据。

#### 标题规则

- 恰好五条，均应具体描述核心主体、动作、反差或结果。
- 五条必须是不同卖点，而非同义改写。
- 禁止纯指代式标题，例如“他做了什么”“接下来发生了什么”。
- 禁止为了吸引点击夸大情绪、规模、因果或结果。
- 推荐标题按准确性、核心信息覆盖、具体性、中文自然度、吸引力依次排序。

#### 简介规则

- 第一段直接交代核心事件和最有辨识度的看点。
- 后续补充能够确认的过程、转折和结果。
- 不把发布账号写成作品名，不声称未执行的字幕、翻译或处理。

#### 标签规则

- 生成十个互不重复的中文可搜索标签。
- 标签来自已确认人物、作品、事件、动作、场景或内容形式。
- 中英文同一实体只占一个标签位；近义短语不能重复凑数。
- 人物和作品标签必须能追溯到 `entities`；来源发布账号默认不得作为标签。
- 证据不足时宁可使用准确的上位内容类型，也不能猜人物或作品。

#### 中文人名规则

- 有中文通行译名时使用通行译名。
- 无通行译名、但身份和原名能够确认时使用规范中文音译。
- 身份无法确认时使用“视频中的男子”“现场主持人”“表演者”等中性称谓。
- 公司、产品、赛事及行业缩写不按人名处理；`SpaceX`、`NBA`、`FIFA`、`OpenAI` 等可保留原文。

### 4. 独立审稿

独立审稿模型接收事实卡和完整文案，输出：

- `approved`；
- `scores`：事实依据、核心贴合度、具体性、中文自然度、吸引力；
- `issues`：具体错误；
- `rewrite_instructions`：只包含可执行的修改要求。

以下情况一票否决：

- 无证据人物、作品、地点、对白、数字、因果或结果；
- 遗漏事实卡中已确认的核心转折或结果，使文案主题偏离；
- 将来源账号当成作品、人物或原创作者；
- 未实际生成字幕却声称“已添加中文字幕”；
- 有中文通行名的人物仍使用英文名，或同一实体中英文重复占标签；
- 标题或标签语义重复、空泛凑数；
- 标签不能追溯到事实卡。

首次审稿不通过时，根据 `rewrite_instructions` 重写一次并再次审稿。第二次仍不通过时：

- 使用只包含 `core_subject + core_event` 的保守事实标题；
- 页面显示“文案需要人工检查”；
- 不静默把低可信文案当作正常结果。

## 前端交互

- 使用 `recommended_title_index` 默认选择系统推荐标题，不再固定选择第一条。
- 推荐候选显示“推荐”标记。
- 需要人工检查时，在标题区域显示明确警告，但允许用户修改后继续。
- 页面语音状态区分“检测到语音、仅用于理解”和“已生成字幕”；本次设计不新增自动字幕功能。
- 旧任务没有推荐索引时继续选择第一条，保证向后兼容。

## 错误处理与降级

- 关键帧不足：内容准备失败，不进入文案生成。
- 转写失败：保留错误原因并继续视觉分析；事实卡必须把对白列为不可确认，审稿不得接受对白型标题。
- 分析模型失败：调用备用模型重试；仍失败则终止任务并提示“无法可靠理解视频内容”。
- 文案模型失败：调用备用模型重试。
- 审稿服务失败：不将未经审稿的文案标记为正常完成；页面进入人工检查状态。
- 任一阶段失败均保留已有视频和封面，便于重新处理，不重复下载。

## 性能边界

- Whisper 在本地运行，不上传音频到额外服务。
- 十张分析帧与转写会增加处理时间，这是“准确优先”的明确取舍。
- 分析帧只用于模型理解，避免前端加载额外图片。
- 正常路径最多三次模型调用：事实分析、文案生成、独立审稿；只有审稿失败才增加一次重写和复审。

## 数据文件

每个任务新增或扩展：

- `analysis_frames/frame01.jpg` 至 `frame10.jpg`
- `visual_timeline.json`
- `transcript.json`
- `content_brief.json`
- `metadata_review.json`
- `result.json` 新增 `recommended_title_index`、`copy_status`，内部审稿依据不暴露给 B 站投稿参数

## 测试与验收

### 确定性测试

- 截图时间覆盖 5% 到 95%，短视频仍生成十个合法时间点。
- 无音轨、无语音、转写成功和转写失败均生成明确状态。
- `content_brief`、文案和审稿 JSON 均通过独立 schema 校验。
- 推荐标题索引必须在 0 到 4；前端默认选中该标题。
- 无证据实体、英文人物名、账号冒充作品、字幕虚假声明和标签语义重复均会被拒绝。
- 旧版 `result.json` 仍可加载和投稿。

### 固定回归样例

- 蒙古派对：事实卡和最终文案必须覆盖结尾马匹，不得只写普通 DJ 现场。
- `The Werewolf`：不得把来源账号自动当成电影名称。
- 星球大战婚礼：人物标签只能来自可确认画面或来源；中文通行名优先。
- 杀手父亲片段：未生成字幕时不得出现“已添加中文字幕”。
- 求婚视频：不得把一人庆祝夸大成“全场起舞”，标签不得用“求婚/现场求婚/求婚成功”重复凑数。

### 完成标准

- 所有现有自动测试和构建通过。
- 上述固定样例通过事实分析、生成和审稿全链路复测。
- 服务重启后可正常处理新任务、重新截图、选择活动和保存草稿。

## 非目标

- 本次不自动烧录或上传字幕。
- 不建立大型人工姓名词典，也不为每条视频进行联网搜索。
- 不自动修改已经保存到 B 站的历史草稿。
- 不以点击率为由允许未经证实的表述。

本设计吸收并取代同日的独立中文人名方案，中文命名作为整套事实约束的一部分实施。
